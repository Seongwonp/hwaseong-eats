## 요약

빈 폴더만 있던 백엔드에 **DB 스키마 · 데이터 48,606건 · 좌표 27,387건 · API 11개**를
채우고 Render 에 배포했다.

```
https://hwaseong-eats-api.onrender.com        (Swagger: /docs)
```

작업 중 **기획서의 핵심 가설 하나를 데이터로 검증**했다 — "소상공인은 존재하지만 검색되지 않는다"(p.4 박순자 사례)가 일화가 아니라 **화성시 가맹점의 60%** 라는 것.

## 1. 시작 상태

`app/` 하위가 전부 빈 `__init__.py` 였다. 문서(`docs/시스템아키텍처.md`, README)는 `main.py` 와 `database.py` 가 있다고 그려놨지만 실제로는 없었고, 아래 명령이 전부 실패하는 상태였다.

```
uv run uvicorn app.main:app --reload   → app.main 없음
uv run alembic upgrade head            → versions/ 디렉토리 없음
```

`alembic/versions/` 는 빈 폴더라 git에 올라가지 않았다. 팀원이 클론하면 마이그레이션이 깨지는 상태.

## 2. 환경 구축

이 개발 환경에는 **PostgreSQL 클라이언트만** 있고 서버 바이너리(`initdb`, `postgres`)가 없었다. root 권한도 docker도 없어서 conda로 PostgreSQL 16.14를 설치하고 사용자 소유 클러스터를 직접 띄웠다.

```bash
initdb -D /home/jovyan/pgdata -U jovyan --encoding=UTF8
pg_ctl -D /home/jovyan/pgdata -o "-p 5432" start
createdb hwaseong_food
```

`uv` 도 없어서 설치했다.

## 3. DB 스키마

### 설계 원칙

**두 데이터를 하나로 뭉치지 않고, 한 테이블에 출처 플래그를 세운다.**
지도에서 칩 조합만으로 필터가 떨어지게 하기 위함이다.

```sql
WHERE is_konapay              -- 화성페이 칩
WHERE is_mobeom               -- 모범음식점 칩
WHERE is_konapay AND is_mobeom -- 둘 다
```

### 테이블 4개

| 테이블 | 용도 |
|---|---|
| `restaurants` | 통합 업소. `is_konapay` / `is_mobeom` 플래그 |
| `users` | 자체계정 (`email` + `password_hash`) |
| `reviews` | `tags[]` + `rating` + `comment` + `earned_points` |
| `point_history` | 포인트 적립·전환 내역 |

`reviews` 는 리뷰 방향이 확정 전이라 **자리만 잡아둔 상태**다. 별점 도입 여부·태그 항목이 정해지면 채운다.

## 4. 데이터 수집

### 4-1. 코나페이 (경기지역화폐) — 48,574건

공개 API 문서가 없어서 [매장 검색 페이지](https://search.konacard.co.kr/payable-merchants)가 쓰는 내부 엔드포인트를 찾아 그대로 호출했다.

```
POST https://search.konacard.co.kr/api/v1/payable-merchants
{"id":"26", "affiliateName":"화성시", "merchantType":"HN",
 "pageNum":"1", "pageSize":"1000"}
```

`id=26` 이 화성시다. 업종코드(`bizType`/`bizTypeNm`)가 있어서 음식점만 거를 수 있고, 2026년 행정구 개편(동탄·만세·병점·효행구)도 반영돼 있다.

**발견한 문제:**

- **주소에 건물번호가 없다.** 1,000건 샘플에서 **0건**. `경기 화성시 병점구 화산중앙로` 처럼 도로명에서 끊긴다
- 좌표는 7%만 제공. 그나마 `0, 0` 이나 타지역 좌표가 섞여 있다
- `id=26` 으로 걸러도 인근 시군 데이터가 소량 섞인다(1,000건 중 8건)
- 상호명에 HTML 엔티티가 남아 있다 (`&#47504;드`)
- 상호명이 중간에 잘린다 (`화성시니어클럽노노카페(근로복지`)
- 가맹점 상세 API는 없다(404). 번지를 더 받아올 구멍이 없다

### 4-2. 모범음식점 — 95건

[공공데이터포털 15153027](https://www.data.go.kr/data/15153027/fileData.do), EUC-KR CSV.
컬럼: `구분 / 음식점명 / 주소 / 전화번호 / 데이터기준일자`. 주소에 **건물번호가 온전히 있다**.

코나페이와 겹치는 가게는 새 행을 만들지 않고 기존 행에 `is_mobeom` 만 세운다. 같은 가게가 두 행으로 갈리면 교집합 필터가 깨지기 때문이다. → **63건 병합, 32건 신규**

### 4-3. 소상공인 상가(상권)정보 — 화성시 46,076건

[공공데이터포털 15083033](https://www.data.go.kr/data/15083033/fileData.do). 이게 판을 바꿨다.

- **국세청·카드사 기반** — 사장님이 카카오에 등록했든 안 했든 다 들어 있다
- **경도·위도가 이미 있다** — 지오코딩이 불필요
- `상권업종대분류명='음식'` 으로 음식점만 거를 수 있다 (화성시 12,954건)
- 도로명주소에 건물번호까지 있다

전국 zip이 352MB, 경기 CSV 하나가 369MB라 **압축을 풀지 않고 스트리밍으로 읽어** 화성시 행만 추출한다.

## 5. 좌표 확보

### 5-1. 카카오 지오코딩

카카오맵 API를 켜는 데 걸림돌이 있었다. 키는 유효한데 이 에러가 났다.

```
App(볏섬) disabled OPEN_MAP_AND_LOCAL service
```

콘솔 `[제품 설정] → [카카오맵] → 활성화 ON` 이 필요했다. 2024년 12월부터 필수가 됐고, **무료 쿼터는 계정당 첫 번째로 활성화한 앱에만** 붙는다.

음식 업종 9,884건을 돌려 **성공 9,869 / 실패 15 (99.8%)**, 18분 소요.

### 5-2. 성공률이 높다고 정확한 건 아니었다

좌표 중복을 검사하니 한 지점에 수십 개가 몰려 있었다. 원인은 **주소 검색 폴백**이다 — 키워드 검색이 실패하면 주소로 찾는데, 코나페이 주소엔 건물번호가 없으니 **도로 중심점 하나**로 찍힌다.

상호명 일치를 확인하는 재검증(`geocode_refine.py`)을 돌려 **863건의 좌표를 교정**했다. 다만 개선폭이 작았다 — 나머지는 **카카오에 그 가게가 아예 없어서** 어떻게 해도 못 찾는다.

> `또곱창`, `카페플랜츠` 는 REST API·지도 웹 검색 양쪽에서 0건.
> 네이버는 캡차로 자동 조회가 막혀 확인 불가.
> 구글은 결제 계정 등록이 필수이고 한국 소상공인 커버리지가 더 낮다.

### 5-3. 폐업 가설 검증 — 기각

"못 찾는 2,168건은 폐업한 가게 아닌가"라는 가설을 코나페이 등록연도로 검증했다.

| 등록연도 | 확인됨 | 미확인 | 미확인 비율 |
|---|---|---|---|
| 2023 | 805 | 1,231 | 60.5% |
| 2024 | 224 | 254 | 53.1% |
| 2025 | 287 | 358 | 55.5% |
| **2026 (올해)** | 210 | 318 | **60.2%** |

폐업이 원인이면 오래된 가게일수록 미확인 비율이 높아야 하는데 **거의 평평하다**. 올해 가맹 등록한 가게도 60%가 카카오에 없다 — 폐업이 아니라 **애초에 등록을 안 한 것**이다.

**기획서 p.4의 박순자 사례가 다수라는 게 숫자로 확인됐다.** 발표에서 쓸 수 있는 근거다.

### 5-4. 상가정보로 해결

상가정보를 상호명+도로명으로 매칭해 **16,263건의 좌표를 카카오 쿼터 소모 없이** 채웠다.

| | 이전 | 이후 |
|---|---|---|
| 좌표 못 믿는 행 | 2,168 | **907** |
| 전체 좌표 보유 | 13,314 | **27,387** |

인증 상태가 바뀌면 적립한 적 없는 포인트를 깎으려 들었다. 작성 시점의 적립액을
`reviews.earned_points` 에 기록하고 그 값만 되돌리도록 고쳤다.

### 도중에 잡은 것

**좌표 `0, 0` 데이터.** `if lat and lng` 에서 파이썬이 `0.0` 을 falsy로 보는 바람에 상태는 `pending` 인데 좌표 컬럼엔 0이 들어갔다. 그대로 지도에 올리면 **기니만 앞바다에 마커가 찍힌다.**

**인증 실패를 "좌표 없음"으로 처리하던 것.** 키가 막힌 채로 돌리면 1만 건이 전부 `failed` 로 오염될 상황이었다. 401/403이면 즉시 중단하도록 고쳤다.

**직접 낸 회귀 1건.** 7번을 고치면서 `road_key` 를 "마지막 토큰"으로 바꿨는데, 모범음식점 주소는 건물번호 뒤에 층·건물명이 더 붙는다.

```
경기도 화성시 동탄구 큰재봉길 23-12, 1층 (동탄구 석우동, 펠리스타)
                                          ↑ '펠리스타)' 가 도로명으로 잡힘
```

52건이 중복 삽입됐다(95 → 147). "첫 숫자 토큰 직전이 도로명"으로 고치고 회귀 테스트를 넣었다. 결과적으로 매칭이 더 정확해져 교집합이 61 → **63건**으로 늘었다.

## 6-1. 성능 최적화

실측해서 느린 곳만 손봤다.

| 쿼리 | 이전 | 이후 |
|---|---|---|
| 상호명 검색 (운영) | **314ms** Seq Scan | **0.3ms** GIN 인덱스 |
| 목록 COUNT | 20ms | 그대로 (Bitmap Index Scan) |
| 반경 조회 | 8ms | 그대로 (좌표 인덱스) |

`ILIKE '%...%'` 는 일반 인덱스를 못 탄다. `pg_trgm` 의 GIN 인덱스를 걸어 1,000배 줄였다.
리뷰는 음식점별 최신순으로 꺼내므로 `(restaurant_id, created_at DESC)` 복합 인덱스를 걸었다.

### 여기서 함정을 하나 발견했다

**로컬에서는 이 최적화 효과가 전혀 안 보인다.**

```
로컬    datcollate = C            → show_trgm('투썸플레이스') = {}
Render  datcollate = en_US.UTF8   → show_trgm('투썸플레이스') = {7개 트라이그램}
```

로컬 DB를 `--locale=C` 로 만들어서, 한글이 단어 문자로 인식되지 않아 트라이그램이 아예
생성되지 않는다. 인덱스를 만들어도 planner 가 쓰지 않는다.

로케일이 다르면 **한글 정렬 순서도 다르다.** 로컬에서 잰 검색 성능과 `ORDER BY name`
결과는 운영과 다를 수 있으니 그대로 믿으면 안 된다.

그리고 트라이그램은 **3글자 이상**부터 동작한다. `본죽`, `치킨` 같은 2글자 검색은
운영에서도 인덱스를 못 타고 184ms 가 나온다.

## 9. 남은 과제

### 미착수

- **절기·축제** — 테이블 자체가 없다. 이번 단계에서는 다루지 않기로 함
- **프론트 연동** — 아직 한 번도 붙여본 적 없음
- **CORS** — 와일드카드 상태. 배포 도메인이 정해지면 좁혀야 함
- **월 1회 데이터 갱신 자동화**

### 결정 대기

| 항목 | 내용 |
|---|---|
| 별점 | 기획서 p.12에 "일부러 뺌"이 차별점으로 박혀 있는데 도입하기로 함. 발표 논리 정리 필요 |
| 리뷰 태그 항목 | 지금은 자유 문자열(개수 10개·길이 20자 제한만). 정해지면 허용 목록으로 바꾼다 |
| 재방문 리뷰 | 현재 한 사람이 한 가게에 한 번만 쓸 수 있다. 방문 단위로 허용하려면 영수증 단위 유니크로 바꿔야 함 |
| 음식 업종 범위 | 현재 6개 업종. 정육점·청과물 포함 여부 |
| 앱 이름 | 레포·카카오 앱은 `볏섬`, 기획서는 `화성뭐먹지?` |

### 알려진 한계

- **`unverified` 907건** — 코나페이 주소에 건물번호가 없고(910건 중 4건만 있음) 상호명도 잘려서 어느 소스와도 매칭이 안 된다. 일부는 실제 폐업일 가능성
- **`geocoding.py` 의 주소 폴백이 살아 있다** — `unverified` 를 만드는 원인이지만 의도적으로 유지 중
- **좌표 겹침은 오류가 아닐 수 있다** — 상가정보는 건물 단위 좌표라 같은 상가건물 업소들이 좌표를 공유하는 게 정상. "단독 좌표 비율"을 품질 지표로 쓰면 안 된다
- **`mobeom.py` 의 CSV URL에 `atchFileId` 하드코딩** — 공공데이터가 갱신되면 조용히 404
